# 构建与发布

## 构建

准备 JDK 21、Node.js 24 和 pnpm 10。仓库自带 Gradle 9.4.0 Wrapper 和生成的 API Client。Folia 的上游提交与源码 SHA-256 由 [upstream.json](../frontstage/folia/upstream.json) 锁定，构建会应用仓库内的补丁和适配代码。

```bash
git clone https://github.com/sky121666/halo-plugin-ncm.git
cd halo-plugin-ncm
./gradlew build
```

Windows 可使用 `gradlew.bat`。产物是 `build/libs/plugin-ncm-*.jar`。完整构建包含 Java 测试、Console 单元测试和类型检查、Folia 适配测试以及前端资源打包。

### 日常开发

| 任务 | 命令或位置 |
| --- | --- |
| Java 测试 | `./gradlew test` |
| Console 测试和类型检查 | `pnpm --dir ui run test:unit --run` 和 `pnpm --dir ui run type-check` |
| Folia 适配测试与构建 | `./gradlew buildFolia`。如需强制重跑，可对该任务使用 `--rerun`。 |
| Halo DevTools | `./gradlew watch -Pport=8092`，需要 Docker。 |
| 生成 API Client | `./gradlew generateApiClient -x test`。相关环境及接口分组由 [build.gradle](../build.gradle) 的 `haloPlugin.openApi` 配置。 |
| 上游加密对照 | 准备固定版本的 `api-enhanced` 及其依赖，生成测试向量后执行 Java 测试。 |

`generateApiClient` 会重新生成 `ui/src/api/generated/`。自定义代码放在生成目录之外。接口移植更新前先固定上游版本，再运行 `python3 tools/convert.py /path/to/api-enhanced/module src/main/resources/ncm-apis.json` 并复核能力级别。

生成对照测试向量时执行以下命令，路径替换为本地上游源码位置。缺少向量时，对应的上游对照测试会跳过。

```bash
mkdir -p src/test/resources
node tools/gen-vectors.js /path/to/api-enhanced > src/test/resources/vectors.json
./gradlew test
```

## 升级与回退

1. 核对新包的 `spec.requires`。本项目当前最低 Halo 版本为 **2.27.3**。留存当前插件 JAR、Halo 数据备份以及用于解密的网抑云密钥。旧 JAR 另行保存，避免后续清理构建目录时被删除。
2. 在「插件 → 网抑云」执行升级。核对启动状态、游客搜索与取址、现有绑定、精选歌单、小播放器及已保存配置。
3. 重启 Halo 后复验同一批设置和绑定，确认游客播放、公开歌单与个人配置可用。
4. 如需还原，在确认停机窗口后使用升级前的插件包及与其匹配的数据和密钥恢复。预先在可丢弃数据上验一遍回退，尤其是涉及凭据和配置迁移的版本。

加密密钥优先使用 `NCM_SECRET_KEY`，也可用 `NCM_SECRET_FILE` 指向持久化文件。默认路径为 `{Halo 工作目录}/plugin-ncm/secret.key`。数据库中的加密绑定需要对应密钥解密，密钥丢失时需重新绑定。 早期测试包若在自定义 Halo 工作目录之外生成了密钥，升级前请让 `NCM_SECRET_FILE` 指向该实例原有的密钥文件，或将原密钥备份后放入实际 Halo 工作目录的 `plugin-ncm/secret.key`。

### 已有站点升级核对项

- 旧账号、设备和代理凭据按可确认的归属迁入 Halo Secret。升级后检查当前用户的绑定和游客状态。
- 站长绑定与精选歌单使用独立的管理授权。需要继续委派站长绑定时，授予「网抑云账号与游客」。
- 旧接口相关缓存秒数可迁入「网络与限流」。公开读取固定使用游客身份，接口按能力和 Halo 授权调用。旧的公开身份、接口范围、额外名单、站长代播及自定义出站 IP 字段保留原存储供兼容。
- 旧音乐 AI 扩展的开关和角色可以迁入主插件。主插件已保存的选择优先。私网或认证代理需要核对部署端的允许列表。 [站点管理与排障](站点管理.md)

## 发布前验收

用确定的源码版本构建候选包。以下以 `0.1.0-beta.1` 为示例，实际版本按拟发布版本填写。

```bash
./gradlew clean build -Pversion=0.1.0-beta.1
jar tf build/libs/plugin-ncm-0.1.0-beta.1.jar
shasum -a 256 build/libs/plugin-ncm-0.1.0-beta.1.jar
git diff --check
```

核对 JAR 文件名、`plugin.yaml` 中的 `spec.version` 与 `spec.requires`、Manifest、UI 入口以及开源许可和 Folia 适配源码。记录最终 JAR 的 SHA-256，同时记录 Git 提交、版本号、Halo 版本和主要验收结果。使用这个 JAR 完成现场验收。[Halo 插件发布验收清单](https://docs.halo.run/developer-guide/plugin/release-checklist)

| 验收项 | 通过条件 |
| --- | --- |
| 全新安装 | 在最低支持的 Halo 版本及计划支持的当前版本安装并启用。用默认配置打开 `/music`，完成游客搜索和试听，核对后台、个人中心和菜单入口。 |
| 账号与授权 | 用普通测试账号完成首次扫码、本人曲库读写和解绑。确认无绑定时使用游客播放，普通用户只能保存自己的偏好，站点默认仅由超级管理员发布。 |
| 配置及升级 | 核对旧配置与绑定升级、重启后的读取，禁用后再启用，检查配置冲突的恢复和升级前数据的回退。 |
| 小播放器 | 发布精选并启用小播放器。普通主题核对整页恢复，已接入的 Swup 主题核对同一引擎连续播放。检查窄屏和亮暗跟随。 |
| 公开能力与可选依赖 | 验证游客完整音源、试听、不可播和错误提示。确认 AI Foundation 未配置时音乐页可用，配置模型后授权身份可生成分词及配色。 |
| 对外承诺的进阶能力 | 以实际部署的反代和浏览器验证登录与个人写入。对变更涉及的手机登录、换绑、代理和上传检查对应真实服务结果。 |

公开测试版至少完成定版构建、全新安装、游客播放及普通用户的绑定和权限验收。稳定版再补齐计划支持的升级、回退、浏览器和进阶能力。卸载及数据清理验证在可丢弃环境进行。
